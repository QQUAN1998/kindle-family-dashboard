# 后续发布步骤 / Release checklist

1. 选一个真实问题：记录触发条件、原表现和改后表现。/ Pick one real issue and record its trigger, before and after behavior.
2. 实现并验证：记录测试命令；说明未测试的设备或线上行为。/ Implement and verify; record commands and untested device or production behavior.
3. 更新中英文说明：更换对应图示或动图，不把流程示意写成实测结果。/ Update both languages and relevant visuals; label diagrams and fixtures accurately.
4. 按项目原有版本规则更新：只有实际软件发布才建对应 Tag/Release；纯文档改动用 docs 提交。/ Follow existing version rules; create software tags/releases for actual releases, and use docs commits for documentation-only work.
5. 提交后核对远端文件和演示链接，再发布社区更新。/ Verify remote files and demo URLs before posting a community update.
6. 在 Insights → Traffic 看近 14 天访客、来源和克隆，结合 Star 与 Issue 判断反馈。/ Review 14-day visitors, referrals and clones in Insights → Traffic alongside Stars and Issues.

建议只在有实际改进时发布，不以空提交或虚构版本制造活跃。/ Publish meaningful improvements, not empty commits or invented releases.
